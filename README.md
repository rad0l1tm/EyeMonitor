# EyeMonitor

Данный проект - локальное Linux-приложение, которое по веб-камере оценивает область взгляда на дисплее. В интерфейс интегрирована мини-игра для динамической оценки качества работы.

Стэк приложения: ```Python + MediaPipe Face Landmarker (CPU) + Qt 6```

Для определения области взгляда используется Ridge-регрессионная модель обучаемая на таких признаках, как матрицы пикселей области глаз и смещении радужки вдоль осей координат. Это дает устойчивость при повороте головы, вращении, а также при отдалении и приближении. Однако, в любом случае, точность зависит от камеры, света, размера глаз в кадре.

## Быстрый запуск: Ubuntu, x86_64

Распакуйте архив и откройте терминал в каталоге `eyemonitor`.

```bash
sudo apt update
sudo apt install python3-venv python3-pip libgl1 libegl1 libopengl0 libglib2.0-0 libxkbcommon0 libxcb-cursor0 v4l-utils
bash scripts/install.sh
.venv/bin/eyemonitor-model
.venv/bin/eyemonitor
```

Нужен **Python 3.10–3.12**, Linux x86_64, glibc ≥ 2.28. При наличии в системе более нового Python используйте вариант с uv ниже. Установка требует интернет; после загрузки модели работа полностью локальная. Модель не включена в архив: `eyemonitor-model` скачивает официальный версионированный task-файл Google по HTTPS, проверяет формат и печатает SHA256. Опционально `--sha256 ДОВЕРЕННЫЙ_ХЕШ` проверяет заранее известный хеш; напечатанный после скачивания хеш сам по себе не подтверждает подлинность.

Для Ubuntu Wayland / Hyprland:

```bash
QT_QPA_PLATFORM=wayland .venv/bin/eyemonitor
```

Для X11: 
```bash
QT_QPA_PLATFORM=xcb .venv/bin/eyemonitor
```

Если камера другая: `v4l2-ctl --list-devices`. Предпочтительно задавать стабильный путь `/dev/v4l/by-id/...-video-index0` через `--camera`. Устройство должно отдавать видеокадры; некоторые `/dev/video*` предназначены только для метаданных.

Пакеты для Qt/OpenCV и камеры (названия могут отличаться по выпуску):

| Семейство | Системные библиотеки и диагностическая утилита |

| Arch / EndeavourOS / Manjaro | `sudo pacman -S --needed mesa libglvnd glib2 libxkbcommon libxkbcommon-x11 xcb-util-cursor v4l-utils` |
| openSUSE | `sudo zypper install libGL1 libEGL1 libOpenGL0 libglib-2_0-0 libxkbcommon0 libxkbcommon-x11-0 libxcb-cursor0 v4l-utils` |

Для единообразной версии Python установите [uv по официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/), затем в каталоге проекта:

```bash
uv python install 3.12
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e .
.venv/bin/eyemonitor-model
.venv/bin/eyemonitor
```

Либо при уже установленном Python 3.12: `PYTHON_BIN=python3.12 bash scripts/install.sh`.

Не устанавливайте зависимости через `sudo pip` в системный Python. ARM/aarch64, Alpine/musl, NixOS и Flatpak не входят в этот вариант поставки: потребуются отдельные сборки и настройка окружения. MediaPipe закреплён на 0.10.21, чтобы использовать известный Tasks API и опубликованные Linux x86_64 wheels для Python 3.10–3.12. Верхние ограничения NumPy и Python намеренные.

## Окружения и мониторы

| Сессия / окружение | Запуск и границы поддержки |
|---|---|
| Hyprland, Sway, river, Wayfire | Нативный Qt Wayland, калибровка в полноэкранном окне |
| GNOME / Mutter, KDE Plasma / KWin Wayland | Тот же Qt Wayland, без специальных разрешений захвата экрана |
| Xfce, Cinnamon, MATE, i3, Openbox, GNOME/KDE X11 | Qt XCB (`QT_QPA_PLATFORM=xcb`) |

Это архитектурная совместимость, **не матрица испытаний на реальном оборудовании**. Программа не использует `hyprctl`, XTest, доступ к глобальному курсору или layer-shell. Поэтому одна реализация работает в обычном окне разных композиторов. Постоянный прозрачный оверлей поверх других приложений и перемещение курсора не реализованы.

```bash
.venv/bin/eyemonitor --list-screens
.venv/bin/eyemonitor --screen 1 --profile ~/.config/eyemonitor/monitor-1.json
```

Смотрите только на выбранный монитор. Координаты нормализованы относительно него; `logical` — локальные логические координаты Qt, не физические пиксели и не глобальные координаты рабочего стола. При дробном масштабе не умножайте их на масштаб вслепую: интеграция должна учитывать систему координат своего получателя. При изменении геометрии/масштаба профиль сбрасывается; при отключении выбранного экрана приложение закрывается.

В Hyprland запускайте из терминала текущей графической сессии. Если пользовательские window rules принудительно отправляют EyeMonitor на другой монитор, отключите это правило: цели должны показываться на мониторе из `--screen`. При проблемах с Wayland-плагином проверьте установку Qt-зависимостей; XWayland fallback возможен через `QT_QPA_PLATFORM=xcb`, если XWayland включён.

## Калибровка и управление

1. Поставьте камеру так, чтобы лицо было видно на камеру. Сядьте примерно в 45–75 см, обеспечьте ровный свет, снимите тёмные очки. Оба глаза должны хорошо читаться в кадре.
2. Нажмите **C**. **Смотрите именно в маленькую точку внутри круга**; чтобы обучать модель распознавания взгляда необходимо последовательно нажимать на круги. При нажатии на круг запоминаются последние за 0.8 секунд кадры; **желательно при нажатии на круг немного двигать головой в разные стороны**, но взгляд от центральной точки не отводить. От размаха движений головой зависит как модель будет после калибровки: если во время калибровки вы почти не двигали головой, то повороты после будут сильно сбивать определяемую область; если активно вращать головой на калибровке, модель будет более устойчива в последствии. 
3. Далее автоматически появятся ещё **5 целей проверки**, не участвующих в обучении. В конце показаны попадания в области и средняя нормализованная ошибка. Это небольшая проверка на месте, не статистическая гарантия точности.
4. Если ошибка большая, то есть несколько сценариев для улучшения качества: 1. Можно повторить калибровку (нажав на клавишу ```C```), предварительно поправив камеру, отрегулировав освещение. 2. Можно, смотря на курсор мыши, нажимать на ЛКМ/тачпад, двигая головой как на калибровке (рекомендуется направлять курсор мыши на близко к границам экрана и в центр).  
Если ошибка велика из-за того что валидация на последних 5 целях (этап 3) была проведена некачественно (был отведен взгляд от центров кругов или из-за частого моргания) - можно повторить валидацию, нажав на клавишу ```V```.
5. Если заметно что "прицел" не доводится до места взгляда, можно просто отрегулировать плавность клавишами ```[``` и ```]```, где первая увеличивает чувствительность, а вторая уменьшает.

| Клавиша | Действие (когда окно в фокусе) |
|---|---|
| C | Калибровка и последующая проверка |
| V | Повторная независимая проверка имеющегося профиля |
| Пробел | Пауза/продолжение анализа; камера остаётся открыта |
| F11 | Полноэкранное отображение сетки |
| Esc | Отмена калибровки, выход из полного экрана, затем выход |
| M | Дообучение курсором (автоматическое считывание) |
| Тап/ЛКМ | Дообучение кликом мыши/тапом по тачпаду |

После проверки окно можно свернуть и читать JSON из другого приложения. Профиль сохраняется в `$XDG_CONFIG_HOME/eyemonitor/profile.json` (по умолчанию `~/.config/eyemonitor/profile.json`), модель в `$XDG_DATA_HOME/eyemonitor/face_landmarker.task`. Профиль содержит коэффициенты и статистику признаков лица; права файла ограничены текущим пользователем. Кадры камеры не сохраняются и не отправляются. Исходящий интернет используется только отдельной командой загрузки модели и установщиками пакетов.

## Производительность на CPU и 16 GB RAM

По умолчанию: **640×480, до 30 анализов/с, одно лицо**, CPU, один поток OpenCV, один последний результат без очереди видеокадров. Это ограничивает рост памяти; обучение — маленькая регрессия, не нейросеть. Веб-камера может вернуть другое разрешение: слишком широкий кадр уменьшается до `--width` перед анализом.

```bash
# Для слабого CPU; мелкие глаза могут ухудшить результат
.venv/bin/eyemonitor --fps 10 --width 320
```

Проект рассчитан на систему без дискретной GPU. Потребление ОЗУ до 400МБ. Для ограничения числа потоков native-библиотек по умолчанию задаются OMP/OpenBLAS/MKL=2, но все внутренние пулы MediaPipe этим не ограничиваются. Замеряйте процесс через `top`, `htop` или `/usr/bin/time -v .venv/bin/eyemonitor`; поле `fps` в JSON — оценка темпа обработки, а не измерение загрузки CPU.

Отключите другие приложения, использующие ту же камеру. Не используйте swap как способ добиться реального времени. При паузе кадры только вычитываются, чтобы после возобновления не анализировать очередь старых кадров. Полностью освободить камеру можно закрытием приложения.

## JSON для интеграций

Никакие данные не записываются, пока не заданы `--output` или `--stdout`:

```bash
.venv/bin/eyemonitor --output /tmp/eyemonitor-state.json
.venv/bin/eyemonitor --stdout > gaze.jsonl
```

`--output` атомарно перезаписывает последнее состояние максимум 10 раз/с и не накапливает историю. `--stdout` выдаёт JSON Lines: перенаправленный журнал **растёт**, его ротация — задача потребителя. Логи MediaPipe идут в stderr. Пример структуры:

```json
{"schema":1,"timestamp":1793491200.0,"monotonic":123.4,"valid":true,"status":"Глаза видны","mode":"track","screen":"DP-1","coordinate_space":"selected-screen-logical","screen_size":[1920,1080],"fps":15.0,"normalized":[0.52,0.47],"logical":[997.88,507.13],"cell":[1,1],"grid":[3,3]}
```

- `normalized`: x,y от 0 до 1, начало слева сверху.
- `cell`: столбец,строка от 0 до 2, появляется после стабилизации области ~200 мс. Это не вероятность.
- `valid=false`, координаты и `cell=null` при потере сигнала, паузе, калибровке, остановке или отсутствии профиля. При смене области старая ячейка может оставаться до истечения dwell, тогда как координата уже движется.
- Потребитель обязан проверять `valid` **и свежесть `timestamp`** (например, не старше 1 секунды): после аварийного завершения файл остаётся. `monotonic` годится только для сравнения на том же Linux-хосте.

Поле confidence намеренно отсутствует: Face Landmarker оценивает ориентиры лица, не вероятность правильной экранной области. Фильтры проверяют видимость глаз и выход за диапазон калибровки, но не выявляют каждую ошибочную оценку.

## Устройство проекта и тесты

- `camera.py`: V4L2, MediaPipe Tasks VIDEO, CPU, ограниченная частота, последний результат под lock.
- `core.py`: координаты радужек в локальных осях глаз, фильтр морганий, признаки положения лица, ridge-регрессия, сглаживание и dwell.
- `app.py`: Qt-интерфейс, 9+5 целей, профили экрана/камеры, JSON.
- `download.py`: отдельная явная загрузка модели.
- `tests/`: 18 проверок вычислений и Qt-цикла калибровки на синтетических данных.
- `requirements-linux-py312.lock`: полный набор зависимостей проверенного окружения Python 3.12.
- `assets`: изображения и аудиофайлы, необходимые для мини-игры.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Подробные результаты и границы проверки: [docs/VALIDATION.md](docs/VALIDATION.md).

Известные ограничения: только один пользователь и один монитор, нет автоматической идентификации человека, камера может продолжить отслеживать другое лицо; не используйте при нескольких людях в кадре. Закрытие одного глаза и плохой свет ухудшают результат.
